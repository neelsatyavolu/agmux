# iPhone app (agmux Remote): how to change it and ship it

The iPhone app is a Capacitor 8 shell around the phone web app. Most changes are
web changes; a few are native Swift; push and pairing also touch the relay.
Read this before editing anything under `remote-mobile/`.

## Where things live

| What | Where |
|---|---|
| The UI (shared with remote.agmux.dev) | `remote-relay/public/app.html` (canonical; `index.html` must stay identical) |
| Bundled copy shipped in the app | `remote-mobile/www/` (generated by `npm run sync-web`; committed; never edit by hand) |
| Native glue (JS) | `remote-mobile/native-bridge.js`: notifications, push, QR scan button, haptics, deep links, resume |
| Native code (Swift) | `remote-mobile/ios/App/App/`: Keychain pairing, QR scanner plugin, AppDelegate push hooks |
| Native settings | `ios/App/App/Info.plist`, `App.entitlements`, `scripts/configure-xcode-project.rb` |
| Relay (WebSocket hub + push sender) | `remote-relay/src/` (`desktop-hub.ts`, `push.ts`, `push-events.ts`) |
| Universal Links file | `remote-relay/public/.well-known/apple-app-site-association` |
| Release tooling | `scripts/release-ios.sh`, `scripts/asc-profile.mjs` |
| App Store checklist, listing, privacy answers | `APP_STORE.md` |

## Rules

- Build with the **release** Xcode (`/Applications/Xcode.app`). `xcode-select` on this Mac points at Xcode-beta, and App Store Connect rejects beta builds. The scripts set `DEVELOPER_DIR` for you.
- Never rename `agmux-remote-auth` (the pairing key mirrored to the Keychain): every phone would unpair.
- Keep `app.html` and `index.html` identical (`cp app.html index.html`), then re-sync `www/` before committing.
- Never commit certificates, `.p8`/`.p12` files, passwords, or 1Password account IDs (public repo). Credentials come from 1Password at build time.
- Don't revoke Apple certificates or delete profiles by hand. `asc-profile.mjs` maintains the App Store profile.
- Deploys (`wrangler deploy`, `vercel --prod`) and secrets (`wrangler secret put`) are outward-facing: ask the user first.
- iPhone only, portrait, iOS 17+, dark. Changing that affects App Review (iPad means more screenshots and review).

## Changing the UI (most changes)

```bash
# 1. edit remote-relay/public/app.html, then
cd remote-relay && cp public/app.html public/index.html && npm test
# 2. bundle it into the app
cd ../remote-mobile && npm run cap:sync
```

- Code that should run only in the app goes behind `html[data-shell]` (CSS), or is wired up by `native-bridge.js` when a native plugin exists (see the `#scanBtn` / `data-scan` pattern).
- The website also needs the change: deploy the relay (`cd remote-relay && npx wrangler deploy`), after asking.
- Demo mode (`startDemo()` in `app.html`) answers like a Mac. Keep it working: App Review uses it.

## Changing native code

- New Swift file in `ios/App/App/`: add it to `SOURCES` in `scripts/configure-xcode-project.rb`, then run
  `GEM_HOME="$(brew --prefix cocoapods)/libexec" ruby scripts/configure-xcode-project.rb` (idempotent).
- A native plugin for the page: subclass `CAPPlugin`, register it in `AgmuxBridgeViewController.capacitorDidLoad()`,
  and reach it from `native-bridge.js` with `Capacitor.registerPlugin('Name')`.
- Capacitor plugin from npm: `npm install @capacitor/<name>@^8 && npm run cap:sync` (updates `ios/App/CapApp-SPM/Package.swift`).
- New permission: add its purpose string to `Info.plist`. Asking without one crashes the app.
- New capability (e.g. iCloud): add it to `CAPABILITIES` in `scripts/asc-profile.mjs` and to `App.entitlements`. The next release turns it on for the App ID and regenerates the profile.
- Regenerating `ios/` (`npx cap add ios --packagemanager SPM`) wipes settings. Afterwards, rerun the configure script and `git checkout -- ios/App/App/Info.plist ios/App/App/Assets.xcassets ios/App/App/SceneDelegate.swift ios/App/App/AppDelegate.swift ios/App/App/App.entitlements`.

## Testing

```bash
(cd remote-relay && npm test)          # web app + relay + push (jsdom / node)
node --test remote-mobile/scripts/*.test.mjs
cd remote-mobile/ios/App && DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project App.xcodeproj -scheme App -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath /tmp/agmux-dd build
xcrun simctl install booted /tmp/agmux-dd/Build/Products/Debug-iphonesimulator/App.app
xcrun simctl launch booted dev.agmux.remote
```

- "Try a demo" exercises every screen without a Mac. A real pairing needs a code from the Mac (Settings → Remote control).
- XCUITest from a scratch project can drive the app with `XCUIApplication(bundleIdentifier: "dev.agmux.remote")`.
  Session rows are buttons labelled "title + time". Endless spinners keep XCUITest waiting for the app to idle.
- Simulators have no camera (the scanner reports UNAVAILABLE) and no real push. Check those on a phone via TestFlight.

## Shipping to TestFlight

```bash
cd remote-mobile && scripts/release-ios.sh             # archive, sign, upload
scripts/release-ios.sh --no-upload                     # signed build/agmux.ipa only
```

- Needs the 1Password CLI signed in to the account that holds the "Apple Distribution Certificate" and "Xanom Apple Dev Creds" items (`OP_ACCOUNT` selects it).
- The build number is the UTC time, so every upload is new. Bump the version (`MARKETING_VERSION` in `configure-xcode-project.rb`, then rerun it) only for App Store releases.
- Apple processes uploads in about 5–15 minutes. The internal TestFlight group **"agmux team"** gets every build automatically, with no review.
- Commit before uploading so the build matches `master`.

## Push notifications

- The relay sends them; the Mac app is not involved. Phones send `push.register` (token + Settings switches), `push.unregister` and `app.state`.
- Alerts: approval or question requested, and a session whose `processing` flips to false. Phones in the foreground are skipped.
- The relay needs the Worker secret: `op read "op://Private/Xanom Apple Dev Creds/AuthKey_4D2Q9WPRZG.p8" | npx wrangler secret put APNS_KEY`.
  Without it the relay answers `push.registered {enabled:false}`, and the app falls back to local alerts.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `exportArchive No signing certificate … found` | Another build on this Mac changed the keychain search list mid-export. Rerun; the script re-adds its keychain before exporting. |
| Upload rejected for SDK/Xcode | It was built with Xcode-beta. Use `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`. |
| Profile missing an entitlement | Add the capability to `CAPABILITIES` in `asc-profile.mjs`; the next release regenerates the profile. |
| QR code opens Safari, not the app | Apple's CDN caches `apple-app-site-association` for hours; reinstall the app after it updates. |
| No push | Check that `APNS_KEY` is set and the relay is deployed, then that iOS notifications are on for agmux. |
